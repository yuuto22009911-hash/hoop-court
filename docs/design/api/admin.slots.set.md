# `admin.slots.set` 🟡

[← action 一覧](./README.md)

> 種別: **管理** ／ 実装: `adminSlotsSet_()`

枠設定を**置き換え・解除**します。[`admin.slots.bulkUpdate`](./admin.slots.bulkUpdate.md) は
追加しかできず、一度閉じた枠を開けられなかったため新設しました。

## 認証

管理トークン。

## payload

| フィールド | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `court_id` | string | ✅ | |
| `from` | ISO8601 | ✅ | 期間の開始 |
| `to` | ISO8601 | ✅ | 期間の終了（**含まない**） |
| `status` | enum | ✅ | `OPEN`（解除） / `CLOSED`（休業） / `BLOCKED`（貸出停止） |

## 戻り値

```json
{ "removed": 1, "added": 2 }
```

| フィールド | 説明 |
| --- | --- |
| `removed` | 削除した既存行の数 |
| `added` | 追加した行の数（残余の再挿入 + 新規行） |

## 処理の流れ

1. 指定期間に**重なる**既存 `Slots` 行を集める
2. はみ出した**前後の残余**を、**元の status のまま**再挿入する
3. 重なる行を削除する（**`_row` の降順**。インデックスずれ防止）
4. `status` が `OPEN` **以外**なら、新しい行を1つ追記する（`OPEN` は削除のみ）

### なぜ残余を再挿入するのか

単純に「重なる行を削除」すると、**広い休業設定の一部だけを開けたときに範囲全体が開いて**しまいます。

```
既存:  09:00 ──────────────── 12:00  CLOSED
指定:          10:00 ─ 11:00         OPEN

結果:  09:00 ─ 10:00  CLOSED   ← 残余（再挿入）
               10:00 ─ 11:00   （行なし = OPEN）
                      11:00 ─ 12:00  CLOSED   ← 残余（再挿入）
```

この例では `removed: 1, added: 2` を返します。

## エラー

| code | 条件 |
| --- | --- |
| `AUTH` / `FORBIDDEN` | 認証・権限 |
| `VALIDATION` | `court_id` が空、`status` が不正、`from` ≧ `to`、日時の形式不正 |

## 挙動の注意

- **`LockService`（20秒）の中で**行の削除と追加を行います
- **他のコートの行は巻き込みません**（`court_id` で絞ってから処理します）
- 冪等です。同じ指定を2回実行しても結果は変わりません
- **客側の空き表示に即反映されます**（`availability.range` が `Slots` を見るため）

## 呼び出し元

管理画面 `/admin/calendar` のセルクリック（1枠ずつの開閉）。

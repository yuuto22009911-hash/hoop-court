## 1. GAS の本番反映（唯一の手動デプロイ）

**`main` にマージしても本番の GAS は変わりません。** 次の手順が必要です。

### 手順

1. **プロジェクトの確認** — Apps Script エディタでスクリプトIDが `11ud1RV7…` で始まることを確認
   - `1NsuHHQr…` は**旧「Hoop Court API」**。2026-07 にアーカイブ済みで、触らない
2. **コードの差し替え** — `main` の `apps-script/Code.gs` 全文をエディタに貼り付けて保存
3. **スキーマ移行** — 関数 `migrateSheets` を実行（§2）
4. **デプロイ** — デプロイ → デプロイを管理 → 稼働中のウェブアプリの**鉛筆アイコン** →
   バージョン「**新バージョン**」→ デプロイ
5. **確認** — `/exec` に GET して `{"ok":true,"data":{"status":"ok","service":"himawari-hoop-court-gas"}}`

### 絶対にやらないこと

> ⚠ **「新しいデプロイ」を作らない。** `/exec` の URL が変わり、
> **LIFF 予約アプリと管理画面が両方止まります。**
> 既存デプロイの「編集（鉛筆）→ 新バージョン」なら URL は変わりません。

問題があれば、同じ画面から**以前のバージョンに戻せます**。

### プロジェクトの見分け方

| | 本番（正） | 旧・使用禁止 |
| --- | --- | --- |
| スクリプトID | `11ud1RV7…` | `1NsuHHQr…` |
| `/exec` に GET | `"service":"himawari-hoop-court-gas"` | `"ping":"pong"` |
| 未知の action | `unsupported action: …` | `unknown action: …` |

## 2. スキーマ移行（`migrateSheets`）

`Reservations` の末尾に不足している列だけを追記する**冪等**な関数です。

```
migrateSheets()
  → "Reservations に列を追加しました: refunded_at, refunded_by"
  → または "追加すべき列はありません（適用済み）。"
```

対象の列（末尾7列）: `source` / `payment_method` / `phone` / `cancel_reason` / `canceled_by` /
**`refunded_at`** / **`refunded_by`**（末尾2つは 2026-08 の返金対応で追加）。

| 項目 | 内容 |
| --- | --- |
| 実行タイミング | コードを貼り付けた後、**再デプロイの前** |
| 何度実行しても安全か | ✅ 安全。不足分だけ追記する |
| `setup()` との違い | `setup()` はヘッダ行があると何もしないため、**既存シートには効かない** |

> 💡 **実行ログにメッセージが出ます**（`Logger.log` を追加しました）。
> それ以前のバージョンでは戻り値がログに出ず何も表示されませんでしたが、
> エラーなく「Completed」で終われば列が揃っていることは同じく確定します。

飛ばした場合は、`admin.reservations.create` / `cancel` / `markRefunded` が
`CONFIG` エラーで止まります（黙って値を捨てないための安全弁）。
`markPaid` は `method` を保存しようとしたときだけ止まります。

## 3. 管理パスワードの変更

### GAS 管理ログイン

1. スクリプト プロパティに `ADMIN_LOGIN_USER` / `ADMIN_LOGIN_PASSWORD` を追加
2. 関数 `setAdminLogin` を実行
3. `AdminAuth` にソルト＋ハッシュで保存され、**平文プロパティは自動削除**される
4. **再デプロイ不要**

> ⚠ 発行済みセッションは即座に無効化されません（`CacheService` に最大6時間）。
> 変更後は管理画面でログアウトしてください。

### Basic 認証（管理画面の入口）

Cloudflare Pages の環境変数を更新し、**再デプロイ**します。
環境変数はビルド時に読まれるため、値を変えただけでは反映されません。

## 4. 本番でのテストの作法

**ステージングがありません。書き込み系のテストは本番データに入ります。**

| 操作 | 作法 |
| --- | --- |
| 予約作成 | 翌日以降の枠を使い、団体名を `テスト予約（削除予定）` にして、**確認後すぐキャンセル** |
| 支払い方法 | **選ばない**（選ぶとその場で売上に計上される） |
| 受付（チェックイン） | **取り消せない。** テスト予約に対してのみ |
| 入金記録 | 売上集計に反映される |
| 一斉配信 | **実行しない。** 友だち全員に実際に届く |
| 枠の開閉 | 客側の空き表示に即反映される。**必ず元に戻す** |

読み取りだけで安全なのは、予約一覧の閲覧・絞り込み、カレンダーの閲覧、`/exec` への GET です。

## 5. 障害時の切り分け

| 症状 | 疑うところ |
| --- | --- |
| `unsupported action: xxx` | **GAS が古い。** 再デプロイ漏れ（§1） |
| 全 action が `CONFIG` | スクリプト プロパティ、またはシートが無い |
| 新しい列だけ `CONFIG` | `migrateSheets` の実行漏れ（§2） |
| 管理画面が `AUTH` | セッション切れ（6時間）。再ログイン |
| LIFF が `AUTH` | IDトークン失効。アプリを開き直す |
| カレンダーが真っ白 | `availability.range` の失敗。コンソールを確認 |
| 予約が「登録中…」のまま | 応答が返っていない。**再送せず一覧で確認**（二重予約防止） |
| `/exec` が 404 | **新しいデプロイを作ってしまった可能性。** URL を確認 |

### ログの見方

Apps Script エディタ → 実行数（Executions）で、関数名・状態・所要時間・エラーが見られます。
`doPost` の失敗はここに記録されます。

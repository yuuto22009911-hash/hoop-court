## 2. 料金（税込・ハーフコート1面）

### 貸切（CHARTER）

| 区分 | 1時間 | 延長30分 |
| --- | --- | --- |
| 平日 朝（9:00〜14:00） | **1,210円** | 660円 |
| 平日 夕（14:00〜20:00） | **1,500円** | 800円 |
| 土日祝（9:00〜20:00） | **1,800円** | （30分単位なし） |

計算方法（`charterPrice_`）:

- **土日祝**: `1時間数 × 1,800円`。端数の30分は課金されない（＝1時間単位でしか予約できない）
- **平日**: 1時間ブロックごとに、**そのブロックの開始時刻**が 14:00 より前なら朝料金、以降なら夕料金。
  余った30分は同じ判定で延長料金を加算

> 例: 平日 13:00〜15:00 → 13時台ブロック（朝 1,210）+ 14時台ブロック（夕 1,500）= **2,710円**

### フリーゴール（FREE）

| 区分 | 30分・1人あたり |
| --- | --- |
| 平日 | **440円** |
| 土日祝 | **550円** |

計算方法（`freePrice_`）: `単価 × 30分の数 × 人数`

> 例: 土曜 10:00〜11:00・3名 → `550 × 2 × 3` = **3,300円**

### 土日祝の判定

`isWeekendOrHoliday_(ymd)` — 土曜・日曜、または `HOLIDAYS` テーブルに載っている日。

> ⚠ **祝日テーブルは 2027年まで**しか登録されていません。2028年以降は平日料金で計算されます。
> 未登録の年を計算すると、GAS の実行ログに次の警告が1回だけ出ます（料金の挙動は変えていません）。
>
> ```
> [holidays] 2028 年の祝日が未登録です（2028-01-01）。祝日が平日料金として計算されます。…
> ```
>
> 更新するときは **3ファイルすべて**を同時に直してください。片方だけだと見積と請求額がズレます。
> `apps-script/Code.gs` の `HOLIDAYS` ／ `hoop-court/src/lib/holidays.ts` ／
> `himawari-site/src/lib/gas/holidays.ts`。翌年分の告示は前年2月ごろに出ます。

## 4. 同時利用のルール

ハーフコート1面を、2つの使い方で共有しています。

| 状況 | 可否 |
| --- | --- |
| 貸切 と 貸切 が重なる | ❌ `P0001` |
| 貸切 と フリー が重なる | ❌ `P0001`（貸切が優先） |
| フリー と フリー が重なる | ⭕ ただし**合計9名まで** → 超過は `P0008` |

`FREE_MAX_HEADCOUNT = 9`

判定対象は **`BLOCKING_STATUSES`（= `CONFIRMED` / `COMPLETED`）の予約**です。
`CANCELED` / `NO_SHOW` は無視されます（来なかった枠は売り直せる方が運用に合うため）。

> 📌 **`COMPLETED`（受付済み）を必ず含めること。** 以前は `CONFIRMED` のみを見ており、
> 「受付後の枠は過去のものだから実害なし」としていましたが、**当日予約の解禁でこの前提は
> 崩れました**。受付済みでも終了時刻が未来の予約があり、`COMPLETED` を外すと
> *受付した瞬間にその枠が空きに戻り、利用中のコートへ別の予約が入ります。*
>
> 例) 10:00–12:00 の貸切を 10:00 に受付 → `COMPLETED` になる → 10:30 に別のお客様が
> 11:00–12:00 を予約できてしまう。
>
> 判定は `isBlockingStatus_()` に集約してあります。**個々の箇所で `status === "CONFIRMED"` と
> 直書きしないでください。**

この判定は3か所で使われ、**すべて同じ基準**で揃えてあります。

| 場所 | 役割 |
| --- | --- |
| `createReservationCore_` | 予約作成時の重複拒否（`P0001`） |
| `availabilityRange_` | 会員向けの空き枠表示 |
| `adminSlotsList_` | 管理カレンダーの占有表示 |

## 5. 予約できる時間（当日判定）

**2026-08 に変更されたルールです。**

| | 判定 |
| --- | --- |
| 旧 | 予約日(YMD) ≦ 今日(YMD) → 拒否 |
| **現行** | **開始時刻 < 現在時刻 → 拒否（`P0005`）** |

つまり **当日でも、開始時刻前なら予約できます。**

この判定は2か所にあり、**同じ基準**で揃えてあります。

| 場所 | 役割 |
| --- | --- |
| `createReservationCore_` | 受付時の拒否（`P0005`） |
| `availabilityRange_` | 表示時の除外（`is_available: false`） |

> **フロントに時刻判定を持たせません。** 「過ぎた枠かどうか」は必ず
> `availability.range` の `is_available` を見てください。
> フロントが持つのは「過去**日**を開かせない」だけです。

### 例外: カウンター受付

`admin.reservations.create` は `allowPast: true` で呼ぶため、**過去時刻でも登録できます。**
受付の入力が事後になる運用に合わせたものです。

## 6. キャンセル規定

| 項目 | 現状 |
| --- | --- |
| キャンセル料 | **0円**（いつでも無料・暫定방針） |
| 会員のキャンセル | マイページから。**本人の予約のみ** |
| 管理者のキャンセル | 任意の予約。`COMPLETED` / `NO_SHOW` からも可 |
| LINE 通知 | **送らない**（会員・管理者とも） |

`reservations.cancel` は `charge_rate: 0` / `charge_amount: 0` を返します。

> 前払い（PayPay 事前決済）を導入する場合、この規定の見直しが必要です。
> 直前キャンセルでも全額返金することになるためです。

## 7. 入金と売上

| 項目 | 内容 |
| --- | --- |
| 支払いタイミング | **ご利用当日、現地の受付にて** |
| 支払い方法 | **現金のみ**（PayPay は加盟店契約が未了で利用不可） |
| 売上集計の対象 | `payment_status = PAID` の予約のみ（`admin.sales.summary`）。**キャンセル済みでも `PAID` なら計上**（§7-C） |

入金が `PAID` になる経路は2つです。

1. `admin.reservations.markPaid` — 受付で入金を記録（`payment_method` も残ります）
2. `admin.reservations.create` で `payment_method` を指定 — **その場で `PAID`**

> ⚠ 2 は「支払い予定」ではなく「**受領済み**」の意味です。管理画面ではその旨を明示しています。

### 7-A. PayPay が使えない理由と、いま何が制限されているか

| 対象 | 状態 |
| --- | --- |
| 店頭（カウンター）での PayPay 支払い | ❌ **加盟店契約が未了のため不可** |
| ネット予約時の PayPay 事前決済 | ❌ 加盟店契約 + オンライン決済 API の申込が別途必要 |
| 現金（当日・現地受付） | ✅ **これだけ** |

手順と再開条件は [`docs/paypay-onboarding.md`](../paypay-onboarding.md)（配布用 PDF あり）。

> **`payment_method` の enum には `PAYPAY` が残っています**（`CASH` / `PAYPAY` / `BANK_TRANSFER`）。
> GAS は値を検証するだけで実際の決済はしないため、送れば通ってしまいます。
> **UI で選ばせないこと。** 管理画面のカウンター受付フォームでは PayPay を
> 「加盟店契約が未了のため選べません」として disabled にしています。

### 7-B. お客様への案内文言（PR #28 で統一済み）

**「PayPay で支払えます」と書かない。** 以下は hoop-court PR #28 で実際に入れた文言です。
他リポジトリ（himawari-site の公開サイト）でも**同じ表現に揃えてください。**

| 場所 | 文言 |
| --- | --- |
| 予約確認画面のポップアップ（見出し） | PayPay でのお支払いについて |
| 〃（本文1） | 現在、PayPay でのお支払いはご利用いただけません（準備中です）。 |
| 〃（本文2） | お支払いは**ご利用当日、現地にて現金**でお願いいたします。 |
| 〃（ボタン） | 確認しました |

| 〃 補足 | PayPay でのお支払いは現在準備中です。ご利用いただけません。 |
| 予約完了画面 | 金額: ¥1,800（当日現地にて現金払い） |
| 利用案内 | お支払いは当日現地で現金にてお願いします（PayPay は現在準備中です）。 |

上記の文言も一斉に戻してください。

### 7-C. 返金

**キャンセルと返金は別の出来事です。**

| 起きたこと | `status` | `payment_status` | 売上 |
| --- | --- | --- | --- |
| 予約を受けた | `CONFIRMED` | `UNPAID` | — |
| 現金を受け取った | `CONFIRMED` | `PAID` | **計上** |
| キャンセルした（返金していない） | `CANCELED` | **`PAID` のまま** | **計上したまま** |
| お金を返した | `CANCELED` | **`REFUNDED`** | **外れる** |

**キャンセルしただけでは売上から外しません。** 返金していなければ入金は現実に存在し、
外すと帳簿と現金が合わなくなるためです（キャンセル料は0円ですが、当日キャンセルで
返金しない運用や、返金が後日になる運用がありえます）。

返金したら `admin.reservations.markRefunded` で `REFUNDED` にします。
**現金手渡しの返金はシステムの外で起きるため、人が実行するまで自動では変わりません。**

> ⚠ **運用に一手増えます。** 「返金したら管理画面で返金を記録する」まで含めて1セットです。
> 忘れると、返したお金が売上に残ります。手順は
> [運用ガイド S-24](../operations/04-scenarios-change.md#s-24)。

`REFUNDED` にしても `paid_at` / `payment_method` は残ります。「もらって、返した」という
順序を残すためです。誤って記録した場合は `admin.reservations.markPaid` で `PAID` に戻せます。

- 無料枠は月200通。**一斉配信は友だちの人数分**を消費します

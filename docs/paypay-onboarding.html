宛先　向日葵株式会社 御中
作成日　2026年7月31日
対象　予約アプリ（LINE）／ 管理画面

この資料のお手続きは、すべて向日葵株式会社さまのお名前で行っていただく必要があります。

PayPay のご契約は、契約者ご本人さまでないとお申し込みができません。恐れ入りますが、開発側で代行することができない仕組みになっております。

お手続きの完了後に発行される3つの情報（本資料「ステップ3」のとおり）をお渡しいただければ、そこから先の作業はすべて開発側で対応いたします。

1. ただいまの状況

店頭（カウンター）での PayPay 支払い ご利用いただけません 加盟店契約がお済みでないため
ネット予約時の PayPay 事前決済 ご利用いただけません 加盟店契約＋オンライン決済のお申し込みが必要
現在のお支払い方法 現金のみ ご利用当日、現地の受付にて

予約アプリの案内文も、上記の実態に合わせて「当日、現地にて現金でお支払い」に修正済みです。 ご予約の確認画面では「PayPay でのお支払いは現在準備中です」というお知らせも表示されます。

2. 全体の流れ

1
PayPay 加盟店のお申し込み
審査に通ると、店頭での PayPay 支払いがご利用いただけるようになります
▼
2
オンライン決済（API）のお申し込み
審査に通ると、ネット予約での事前決済を作れるようになります
▼
3
発行された3つの情報を開発側へお渡し
実装 → テスト → 公開（開発側の作業です）
ステップ1 だけでも、先に進める価値があります

加盟店契約が通った時点で、カウンターでの PayPay 支払いだけ先に始められます。 アプリの改修は不要で、案内文を直すだけで対応できます。 ネット予約の事前決済は、ステップ2・3まで進んだあとになります。

  • 法人の情報（法人番号、登記上の商号・所在地）
  • 入金先の銀行口座（法人口座を推奨。屋号と名義が一致していると審査がスムーズです）
  • 事業の実態がわかるもの（施設の写真、ウェブサイトの URL など）

内容によっては、お電話での確認や追加書類のご提出をお願いされることがあります。 全体を通して、ここが一番お時間のかかる工程です。早めの着手をおすすめいたします。

補足

  • 法人・個人事業主のどちらでもお申し込みいただけます。
  • 決済ごとに手数料が発生します。料率はお申し込み時のご案内をご確認ください（プランにより異なります）。

4. ステップ2 ｜ オンライン決済（API）のお申し込み

加盟店契約とは別のお申し込みになります。ネット予約時に PayPay でお支払いいただけるようにするには、こちらも必要です。

  1. 開発者向けサイト PayPay for Developers（https://developer.paypay.ne.jp/）にご登録いただきます
  2. オンライン決済（API）の利用をお申し込みいただきます
  3. 「PayPay オンライン決済に関する API 利用特約」にご同意いただきます
    https://about.paypay.ne.jp/terms/merchant-online/rule/api/
  4. 審査を経て、次の3つの情報が発行されます

こちらも審査があり、すぐには発行されません。ステップ1が終わり次第、続けてお進めください。

5. ステップ3 ｜ 開発側にお渡しいただく情報

PayPay for Developers の管理画面に、次の3つが表示されます。これを開発側にお渡しください。

MERCHANT_ID（マーチャントID）加盟店を識別する ID
API_KEY（APIキー）API を使うための ID
API_SECRET（APIシークレット）秘密の鍵。パスワードと同じお取り扱いが必要です
テスト環境の情報だけ、先にいただけると助かります

管理画面にはテスト環境と本番環境の切り替えがあり、それぞれ別の値になります。 先にテスト環境の3つをお渡しいただければ、本番の審査をお待ちいただく間に開発を進められます。

お受け渡し方法のお願い

API_SECRET が第三者に漏れると、向日葵株式会社さまのお名前で決済を作られてしまうおそれがあります。次のお取り扱いをお願いいたします。

✕ お避けください
  • メール・LINE・チャットの本文に貼る
  • スクリーンショットを共有フォルダに置く
○ おすすめの方法
  • 画面共有をしながら口頭でお伝えいただく
  • パスワード管理ツールを利用する
開発側での取り扱い

お預かりした値は、GitHub などのコード置き場には一切保存いたしません。 Google Apps Script の「スクリプト プロパティ」に直接ご入力いただく形にいたしますので、 開発側が値を保持し続けることもございません。

6. 3つの情報をいただいたあとの作業

ここから先は開発側の作業です。ご参考までに、おおよその規模をお示しします。

作業目安
決済のしくみを組み込む（決済作成・入金確認・返金）2〜4人日
予約アプリ側の画面（PayPay へ移動 → 戻ってきて予約確定）2〜3人日
管理画面（未決済の予約・返金ボタン）1人日
テスト環境での検証＋実機（スマートフォン）での往復テスト1〜2人日
合計6〜10人日

公開前に、テスト環境で「決済 → 予約確定 → キャンセル → 返金」までひととおり通します。 そのあと本番環境で少額の実決済を1件テストしてから公開いたします。

7. 決まっていること／これからお決めいただきたいこと

決定済み

事前決済の対象ネット予約のみ（カウンター受付は現地払いのまま）
決済のタイミングご予約時に全額決済
キャンセル時の返金管理画面から手動で返金（自動返金にはしない）

これからお決めいただきたいこと

① キャンセルの返金ルール（優先度：高）

現在は「いつでも無料でキャンセル可」となっております。前払いに変わりますと、 直前のキャンセルでも全額を返金することになります。 「〇日前までは全額返金、それ以降は返金なし」といったルールを設けるかどうか、ご検討ください。

② 当日のご予約の扱い

当日枠もネット予約で前払いにするか、当日はカウンター受付のみにするか。

③ 特定商取引法の表記

前払いに変わると「支払時期」と「返金の条件」の記載変更が必要です。 ①のルールが決まり次第、こちらで文面をご用意いたします。

8. よくあるご質問

加盟店のお申し込みだけ先に済ませてもよいですか？

はい、むしろその方がおすすめです。ステップ1が通れば、店頭での PayPay 支払いだけ先に始められます。

審査に落ちることはありますか？

可能性はございます。その場合は理由に応じた再申請となりますので、ご連絡ください。

費用はかかりますか？

決済ごとに手数料が発生します。料率はお申し込み時のご案内をご確認ください。開発側の作業費とは別になります。

開発側で代わりに申し込んでもらえませんか？

申し訳ございません、できかねます。契約者ご本人（代表者さま）の本人確認と銀行口座の登録が必要なためです。お申し込み画面の入力でご不明な点がございましたら、画面を見ながらご説明いたします。

この資料は 2026年7月時点の情報をもとに作成しています。PayPay 側のお手続きや画面は変更されることがありますので、 実際のお申し込み画面のご案内を優先してください。

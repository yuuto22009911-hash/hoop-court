## 登場するシステム（4つだけ）

| 記号 | 名前 | 誰が使う | 何ができる |
| --- | --- | --- | --- |
| 📱 | **LIFF 予約アプリ** | お客様 | 空き確認・予約・自分の予約のキャンセル |
| 🖥 | **管理画面** | 運営 | 予約一覧・受付・入金記録・代理予約・枠設定・配信・売上 |
| ⚙ | **GAS（バックエンド）** | 直接は触らない | すべての判定と読み書き。裏で必ず通る |
| 📊 | **スプレッドシート** | 運営（例外時のみ） | 唯一の正データ。**通常は直接編集しない** |

```
   📱 お客様のアプリ ──┐
                       ├──▶ ⚙ GAS ──▶ 📊 スプレッドシート
   🖥 運営の管理画面 ──┘
```

> **すべての操作は必ず ⚙ GAS を通ります。** 画面が違っても、判定（空き・金額・重複）は
> 同じ場所で行われます。だから「アプリで取れた枠がカウンターでも埋まっている」が成立します。

## シナリオの読み方

各シナリオは同じ形で書いてあります。

- **場面** — どんなときか
- **使うもの** — 📱 / 🖥 / 📊 のどれか
- **流れの表** — 誰が / どの画面で / 何をすると / どの action が動き / データがどう変わるか
- **失敗するとき** — よくある失敗と、そのときの表示
- **注意** — 取り返しがつかない操作など

---

## 全体で守ること

| # | 決まり | 理由 |
| --- | --- | --- |
| 1 | **スプレッドシートを直接編集しない** | 判定を通らないため、二重予約や金額のズレが起きる。例外は[トラブル編](./06-scenarios-trouble.md)のみ |
| 2 | **受付（チェックイン）は取り消せない** | 逆操作の機能が無い。押す前に予約番号を読み上げて確認する |
| 3 | **一斉配信は友だち全員に届く** | テストで押さない。無料枠を人数分消費する |
| 4 | **支払い方法を選ぶ＝入金済み** | 「予定」ではなく「受領済み」の記録。売上に計上される |
| 5 | **応答が返らないとき、同じ操作を繰り返さない** | 二重予約になる。一覧で検索して確認する |

# トラブル対応（T-01〜T-10）

[← 運用ガイド](./README.md)

**画面に出た言葉から探してください。**

---

## T-01

### 「登録中…」のまま戻ってこない 🖥

**絶対にやってはいけないこと**: **もう一度「登録する」を押すこと。**

サーバー側では**予約が成立している可能性が高い**ためです。押し直すと**二重予約**になります。

| # | 対応 |
| --- | --- |
| 1 | 30秒待つ。「登録できたか確認できませんでした」の画面に切り替わる |
| 2 | 「一覧で確認する」を押す |
| 3 | **団体名で検索する** |
| 4 | 見つかった → 登録成功。金額を確認してお客様に伝える |
| 5 | 見つからない → 登録されていない。もう一度登録する |

> 💡 画面が自動で切り替わり、再送信ボタンは無効化されます。迷わず一覧で確認してください。

## T-02

### `unsupported action: ...` と表示される 🖥

**原因**: **GAS が古いままです。** その action がまだ本番に反映されていません。

| # | 対応 |
| --- | --- |
| 1 | 表示された action 名を控える |
| 2 | 開発側に連絡する |
| 3 | Apps Script の再反映が必要 → [設計書 05-operations](../design/05-operations.md) §1 |

**現場での回避**: その機能は使えません。代替手段は下表のとおりです。

| 使えない機能 | 代替 |
| --- | --- |
| カウンター受付 | お客様に LINE から予約してもらう |
| 管理者キャンセル | お客様本人にアプリからキャンセルしてもらう |
| カレンダーの色分け・枠クリック | 一括設定フォームを使う |

## T-03

### アプリのカレンダーが真っ白・全部「—」 📱

| 状況 | 判断 |
| --- | --- |
| **開いた直後の数秒だけ** | 正常。「空き状況を読み込んでいます…」と出て、すぐ記号に変わる |
| **10秒以上そのまま** | 異常 |

**異常のときの対応**

| # | 対応 |
| --- | --- |
| 1 | アプリを閉じて開き直す |
| 2 | 🖥 管理画面のカレンダーが表示できるか確認する |
| 3 | 管理画面も駄目なら **GAS 側の障害**。開発側に連絡 |
| 4 | 管理画面は正常なら、お客様の端末・通信の問題の可能性 |

**暫定対応**: 電話で予約を受け、カウンター受付で登録してください（[S-06](./02-scenarios-booking.md#s-06)）。

## T-04

### 管理画面に入れない 🖥

**どちらで止まっているかで原因が違います。**

| 止まる場所 | 原因 | 対応 |
| --- | --- | --- |
| **ブラウザのダイアログ**（ID/パスワード） | Basic 認証 | パスワードを確認。変更直後なら**再デプロイ待ち**の可能性 |
| **画面内のログインフォーム** | 管理ログイン | パスワードを確認。`admin.login` の認証 |
| ログイン後すぐ戻される | セッション切れ（6時間） | もう一度ログインする |

> 💡 **ID は同じでもパスワードは別**です。二層あることを思い出してください。

**「IDまたはパスワードが違います」**: 管理ログインのパスワードが違います。
変更した場合、`setAdminLogin` の実行が済んでいるか確認してください。

## T-05

### 誤って受付（チェックイン）してしまった 🖥

> ⚠ **システムでは取り消せません。**

| # | 対応 |
| --- | --- |
| 1 | 📊 スプレッドシートの `Reservations` を開く |
| 2 | 該当の行（`display_number` で探す）を見つける |
| 3 | `status` を `COMPLETED` → `CONFIRMED` に戻す |
| 4 | `checked_in_at` を**空にする** |

**両方を直してください。** どちらか片方だけだと、次に受付しようとしたとき
`ALREADY_CHECKED_IN` になります。

> ⚠ **列の並べ替え・削除は絶対にしないでください。** セルの値だけを直します。

---

## T-06

### 誤って入金を記録してしまった 🖥

> ⚠ **システムでは取り消せません。** 売上に計上されたままになります。

| # | 対応 |
| --- | --- |
| 1 | 📊 スプレッドシートの `Reservations` を開く |
| 2 | 該当の行の `payment_status` を `PAID` → `UNPAID` に戻す |
| 3 | `paid_at` を空にする |

直さないと[売上集計](./05-scenarios-slots.md#s-22)に残り続けます。

---

## T-07

### 同じ枠に二重予約が入ってしまった 🖥

**通常は起きません**（GAS が重複を弾きます）。起きるとすれば、[T-01](#t-01) の状況で
登録を押し直した場合です。

| # | 対応 |
| --- | --- |
| 1 | 🖥 予約一覧で両方の予約番号を確認する |
| 2 | **後から作られた方**をキャンセルする（`created_at` が新しい方） |
| 3 | 理由に「二重登録のため」と入れる |
| 4 | 入金済みなら[T-06](#t-06)も行う |

**お客様が2組いる場合**（本当に重複して受けてしまった）: どちらかに別の時間を案内するしかありません。

## T-08

### お客様に予約完了の LINE が届かない 📱

**予約自体は成立しています。** 通知の失敗で予約が消えることはありません。

| 原因 | 確認方法 | 対応 |
| --- | --- | --- |
| **公式アカウントを友だち追加していない** | 最も多い | 友だち追加をご案内する |
| 通知機能が未設定 | 他のお客様にも届いていない | 開発側に連絡（`LINE_MESSAGING_TOKEN`） |
| 無料枠を使い切った | 月200通 | 翌月まで待つか、配信を控える |

**確認**: 🖥 予約一覧にその予約が出ていれば成立しています。予約番号をお伝えください。

---

## T-09

### 売上と実際の現金が合わない 🖥

**多い順に確認してください。**

| # | 原因 | 確認方法 |
| --- | --- | --- |
| 1 | **入金記録の忘れ** | 予約一覧の「完了」タブで**未入金**を探す |
| 2 | **キャンセル分が残っている** | 「キャンセル」タブで**入金済み**を探す（[S-15](./04-scenarios-change.md#s-15)） |
| 3 | 誤って入金記録した | [T-06](#t-06) |
| 4 | 日付の基準の違い | 売上は**利用日**で集計。入金日ではない |

> 💡 2 が一番見落とされます。**キャンセルしても `PAID` なら売上に残ります。**

## T-10

### 土日祝なのに平日料金で計算される 🖥

**2028年以降に起きます。** 祝日テーブルが 2027年までしか登録されていないためです。

| 状況 | 判断 |
| --- | --- |
| 土曜・日曜なのに平日料金 | **異常。** 開発側に連絡 |
| 祝日なのに平日料金（2028年〜） | **既知**。テーブルの更新が必要 |
| 祝日なのに平日料金（2027年まで） | 異常。テーブルの登録漏れ |

**暫定対応**: 正しい金額を口頭でご案内し、差額を手元で管理してください。
システムの `total_amount` は自動では直りません。

## T-11

### 「予約番号に一致する予約が2件あります」と出た 🖥

**場面**: 受付やキャンセルで予約番号を入れたら、実行できずにこのメッセージが出た。

```
予約番号「R-2026-08-01-1111」に一致する予約が 2 件あります。
一覧から対象を選ぶか、予約IDで指定してください。
```

**故障ではありません。安全装置です。** 予約番号は末尾4文字が予約IDの先頭4文字で、
**同じ日に偶然かぶることがあります**。そのまま進むと**別のお客様の予約を操作**して
しまうため、システムが手前で止めています。

| # | 対処 |
| --- | --- |
| 1 | 🖥 予約一覧をその番号で検索する |
| 2 | 団体名・時間・人数で**どちらが目の前のお客様か**を確認する |
| 3 | 一覧から対象を選んで操作する（番号を打ち直さない） |

> 💡 **確定済みの予約が1件だけなら、このメッセージは出ません。** システムが自動で
> そちらを選びます。出るのは、キャンセル済みや受付済みが複数ある場合です。

**お客様への案内**: 「同じ番号のご予約が重なっているため確認します」で十分です。
番号を言い直してもらっても変わりません。

## 連絡するときに伝えること

開発側に連絡するときは、次を添えてください。**原因の特定が早くなります。**

- **画面に出ているメッセージの全文**（`unsupported action:` ならその action 名も）
- どの画面で、何をしたときか
- 予約番号（分かれば）
- 時刻

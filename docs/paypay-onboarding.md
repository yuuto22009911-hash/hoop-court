## 0. いまの状態

| | 状況 |
| --- | --- |
| 店頭（カウンター）での PayPay 支払い | **使えません**（加盟店契約が未了のため） |
| ネット予約時の PayPay 事前決済 | **使えません**（加盟店契約 + オンライン決済の申込が必要） |
| 現在のお支払い方法 | ご利用当日、現地にて**現金**のみ |

予約アプリの案内文も、上記に合わせて「当日現地にて現金でお支払い」に修正済みです。
ご予約確認画面では「PayPay は現在準備中です」というお知らせも表示されます。

## 1. 全体の流れ（3ステップ）

```
 ステップ1  PayPay 加盟店の申し込み          → 通ると「店頭での PayPay」が使えます
      ↓
 ステップ2  オンライン決済（API）の申し込み  → 通ると「ネット予約の事前決済」が作れます
      ↓
 ステップ3  発行された3つの情報を開発側へ    → 実装・テスト・公開
```

**ステップ1だけでも先に価値があります。** 加盟店契約が通った時点で、カウンターでの
PayPay 支払いが可能になります（アプリの改修は不要です。案内文だけ直します）。
ネット予約の事前決済はステップ2・3まで進んだあとになります。

## 2. ステップ1: PayPay 加盟店の申し込み

### どこから申し込むか

| | |
| --- | --- |
| 案内ページ | https://paypay.ne.jp/store/ |
| 申込フォーム | https://business.paypay.ne.jp/entry/ |
| 導入の流れ | https://paypay.ne.jp/store/introduction/ |
| 電話で相談 | 0120-957-640（10:00〜19:00・年中無休） |

> リンクが変わっていた場合は、PayPay 公式サイト（https://paypay.ne.jp/）の
> 「加盟店の方はこちら」から進んでください。

### ご用意いただくもの

- **代表者さまの本人確認書類**（運転免許証・マイナンバーカードなど）
- **法人の情報**（法人番号、登記上の商号・所在地）
- **入金先の銀行口座**（法人口座を推奨。屋号と名義が一致していると審査がスムーズです）
- **事業の実態がわかるもの**（施設の写真、ウェブサイトの URL など）

### 期間の目安

申し込みから利用開始まで**数日〜数週間**です。内容によっては電話確認や追加書類の提出を
求められることがあります。**ここが全体で一番時間がかかる工程**なので、早めの着手をおすすめします。

### 補足

- 法人・個人事業主のどちらでも申し込めます。
- 決済手数料が発生します。料率は申込時の案内でご確認ください（プランにより異なります）。

## 3. ステップ2: オンライン決済（API）の申し込み

加盟店契約とは**別の申し込み**です。ネット予約時に PayPay で支払えるようにするには、
こちらも必要になります。

1. 開発者向けサイト **PayPay for Developers**（https://developer.paypay.ne.jp/）に登録します
2. オンライン決済（API）の利用を申し込みます
3. 「PayPay オンライン決済に関する API 利用特約」に同意します
   （https://about.paypay.ne.jp/terms/merchant-online/rule/api/）
4. 審査を経て、後述の**3つの情報**が発行されます

こちらも審査があり、すぐには発行されません。ステップ1が終わり次第、続けてお進めください。

---

## 4. ステップ3: 開発側にお渡しいただく情報

PayPay for Developers の管理画面に、次の3つが表示されます。**これを開発側にお渡しください。**

| 項目 | 内容 |
| --- | --- |
| `MERCHANT_ID`（マーチャントID） | 加盟店を識別する ID |
| `API_KEY`（APIキー） | API を使うための ID |
| `API_SECRET`（APIシークレット） | **秘密の鍵。パスワードと同じ扱いが必要です** |

管理画面には**テスト環境**と**本番環境**の切り替えがあり、**それぞれ別の値**になります。
可能であれば、**先にテスト環境の3つ**をお渡しください。本番の審査を待つ間に開発を進められます。

### ⚠ 受け渡し方法のお願い

`API_SECRET` が漏れると、第三者が向日葵株式会社さまの名義で決済を作れてしまいます。

- ❌ メール・LINE・チャットの本文に貼らない
- ❌ スクリーンショットを共有フォルダに置かない
- ⭕ 画面共有しながら口頭で伝える、またはパスワード管理ツールを使う

お預かりした値は、GitHub などのコード置き場には**一切保存しません**。
Google Apps Script の「スクリプト プロパティ」に直接ご入力いただく形にしますので、
開発側が値を保持し続けることもありません。

## 5. 3つの情報をいただいたあとの作業（開発側）

| 作業 | 目安 |
| --- | --- |
| 決済のしくみを組み込む（決済作成・入金確認・返金） | 2〜4人日 |
| 予約アプリ側の画面（PayPay へ移動 → 戻ってきて予約確定） | 2〜3人日 |
| 管理画面（未決済の予約・返金ボタン） | 1人日 |
| テスト環境での検証＋実機（スマホ）での往復テスト | 1〜2人日 |
| **合計** | **6〜10人日** |

公開前に、テスト環境で「決済 → 予約確定 → キャンセル → 返金」までひととおり通します。
そのあと本番環境で少額の実決済を1件テストしてから公開します。

## 6. 決まっていること／これから決めていただきたいこと

### 決定済み

| 項目 | 決定 |
| --- | --- |
| 事前決済の対象 | **ネット予約のみ**。カウンター受付は現地払いのまま |
| 決済のタイミング | **予約時に全額決済** |
| キャンセル時の返金 | **管理画面から手動で返金**（自動返金にはしない） |

### これから決めていただきたいこと

1. **キャンセルの返金ルール** — 現在は「いつでも無料でキャンセル可」です。前払いに変わると、
   直前キャンセルでも全額返金することになります。「〇日前までは全額返金、それ以降は返金なし」
   といったルールを設けるかどうか。
2. **当日のご予約** — 当日枠もネット予約で前払いにするか、当日はカウンター受付のみにするか。
3. **特定商取引法の表記** — 前払いになると「支払時期」と「返金の条件」の記載変更が必要です。
   1.のルールが決まり次第、こちらで文面を用意します。

## 7. よくあるご質問

**Q. 加盟店の申し込みだけ先に済ませてもいいですか？**
はい。むしろその方が良いです。ステップ1が通れば、店頭での PayPay 支払いだけ先に始められます。

**Q. 審査に落ちることはありますか？**
可能性はあります。その場合は理由に応じた再申請になりますので、ご連絡ください。

**Q. 費用はかかりますか？**
決済ごとに手数料が発生します。料率は申込時の案内をご確認ください。
開発側の作業費とは別です。

**Q. 開発側で代わりに申し込んでもらえませんか？**
できません。契約者ご本人（代表者さま）の本人確認と銀行口座の登録が必要なためです。
申込画面の入力でご不明な点があれば、画面を見ながらご説明します。
